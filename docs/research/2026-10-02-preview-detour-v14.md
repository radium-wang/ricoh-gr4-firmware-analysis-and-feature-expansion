## 原厂接入点

原始 `0x536438A0` 的 8 字节为 `2c0b09eb083090e5`，对应 `BL 0x53886558` 及 `LDR r3,[r0,#8]`；继续位置为 `0x536438A8`。此时 recipe 位于现场寄存器 **r4**，不能把它误当 C 函数的 r0 入参。该点位于 BD6/BD8/BE4/BE6 原厂重建之后。

原厂 singleton 查询 `0x53886558` 被保留，在改道中执行一次。汇编随后将 r4 传给 `gr4_xpan_preview_recipe_regenerated_native`，再恢复原返回 r0/r1/r2、所需现场状态和 NZCVQ 条件标志，执行原 `LDR r3,[r0,#8]`，重现原 BL 的 LR=`0x536438A4`，跳到继续位置。r12 是调用临时寄存器且下一条原指令重写它；不承诺其无用中间值与原代码相同。栈始终满足原 C ABI 的八字节对齐。

两条指令改成 `LDR pc,[pc,#-4]` 加目标地址字。这允许离线模型跳到远处的候选代码，但要求两个字的修改期间原任务停止，否则可能把旧第二条指令当地址。原地址、候选字、恢复原值都在 manifest 的 `hook_words` 中；不是单条原子更新。

## 原生边界和恢复

原 helper adapter 与重建后的 adapter 共用 `checked_binding`，继续限制已经建模的 ordinary still owner、同一 recipe/manager/collection、source0、external0、尺寸档7/29/30、原倍率和 native aspect0。未启用的 binding 在解引用 process 前即拒绝；新增了停用 binding 带失效 process 地址的检查。

source2/resolution3/external1 的实机 manager **未被放宽接入**。八个集合槽为空仍表示 owner 关系未建立，不能据模型宣布候选在该实机路径有效。ready 是调用者的暂停/排空契约，不是硬件证明。

重建后的函数只协调 v13 已证实的“原高度＋已知 XPAN Y”组合，再用既有 apply 完成尺寸/倍率/计划检查。未知状态不改。局部 recipe 撤销和指令撤销分开核对；卸载前仍须恢复发布给其他任务的属性/窗口、停止新调用及排空旧调用，然后才可解除 binding/释放代码。
