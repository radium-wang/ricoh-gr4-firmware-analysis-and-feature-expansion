# GR IV 第五项菜单原生入口与恢复（v16）

日期：2026-10-02。目标版本：01.11.10.07。本轮只读电脑固件样本，未连接、写入相机或 SD 卡；XPAN 尚未实装。

## 本轮完成

- 将“原厂刷新完成后显示第五项”拆为独立助手，防止入口拦截时重复调用自身。
- 编译五个原生 ABI 入口：刷新、激活、事件、列表确认、按钮 std::function 调用。只拦截绑定的原厂 SelectMenuController 的第 34 行；其他对象/行转回原厂。
- 保留事件原生返回值 0；按钮仅确认和关闭一次。三个确认入口遇到 readiness 不完整、无第五个已构造槽或越界索引时拒绝调用四项原厂表。
- 保留 std::function 的 owner record 与 manager；入口拦截未改动其存储/释放路径。
- 将五处原厂入口各八字节固定到样本 SHA256，并生成十个原值/替换值的撤销清单。原厂回跳代码保留寄存器、标志和栈，包括 PUSH PC 保存的原厂地址。
- 撤销助手在所有图像读者暂停、局部图像改动撤销、readiness 清零后，恢复先前的四种画幅之一，并先清除共享计划，再调用原厂属性观察者与四项刷新。恢复入口字并完成缓存发布、清空在途调用后才能解绑和释放。

## 验证与边界

`settings-entry-hooks-arm-v3/checks.json`：94 项 ARM 检查通过。实际执行补丁后的入口、编译后的项目代码、回跳前两条原厂指令以及原厂列表计数、导航和矩形代码；**其余原厂 UI 方法体、文字/属性/生命周期服务使用模型**。两种标志状态下逐一比较五个回跳的全部寄存器、标志和保存栈。覆盖三个确认入口、三种 crop 的共享计划、内层原厂确认触发再次刷新、单次关闭和撤销。

`settings-entry-hooks-arm-v3/transaction-checks.json`：32 项主机故障模型，通过编译后的 `xpan_hook_txn.c` 验证真实清单中的十个字。包含每一字提交后报错、每一处撤销写失败、缓存发布失败、每一字出现未知值；未知值不被覆盖，恢复未完成时持续保持暂停。**原生任务暂停和缓存服务仍未验证**。

`settings-routes-native-v3/checks.json`：56 项既有导航/刷新/确认回归检查通过。

构建脚本的 0x61000000 是模拟器地址，不是可用相机地址。载荷不是升级包，也不是 SD 安装包。本轮保存了第一次受限沙箱无法读取 CPU 缓存信息的失败；随后在允许的本机离线环境中运行成功。

## 仍然需要完成

这些入口位于原厂代码段，早期实测页表显示相关菜单段为只读。**本轮没有证明可以通过现有 USB/SD 通道直接写入这些入口**；十字撤销模型也不是实际相机上的恢复通道。

该方案可作为后续固件修改的明确拦截基线。优先继续分析对象级 RAM 接入：克隆并绑定原对象虚表的激活/事件槽、仅替换两个 std::function invoker、在返回后重新呈现第五项，并核对全部直接刷新调用者是否覆盖，避免依赖代码页可写这一未证明前提。原虚表只有 16 项，没有直接指向 0x531DA9D4 的刷新槽。

实装前还需：真实图像源/preview recipe 所有关系、稳定的几何参数来源、UI/拍摄任务暂停与清空协议、图标到原绘制系统的接入、预览及真实 JPEG/DNG 输出和撤销验证。不能用模型 readiness=15 代替实机验证。

## 复现

```sh
python3 -B tools/check_gr4_settings_hooks.py --out /tmp/gr4-settings-hooks-new
python3 -B tools/check_gr4_settings_hook_transaction.py --package /tmp/gr4-settings-hooks-new
```

在 macOS 受限沙箱中 Unicorn 可能无法读取 CPU 缓存信息；这些命令仅使用本机文件和模拟器，不枚举相机。不覆盖已保存的输出目录。
