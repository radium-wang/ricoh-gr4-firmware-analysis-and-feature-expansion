# GR IV 1.11 升级版本检查：离线分析

本记录只对应本地官方 `fwdc248b.bin` 样本，包头显示 `1.11.10.7`。没有把修改包交给相机，也没有证实相机会接受它。

## 已定位的比较逻辑

解码载荷中 `Update Version is older than Current Version!!` 位于文件偏移 `0xFC19F8`、运行地址 `0x53FA9CE8`。引用该字符串的检查函数从 `0x5383171C` 开始；上层更新流程在 `0x53A914F4` 和 `0x53A91B50` 调用它。函数按更新类型选择 CPU、SRIC、DSP 等组件的比较路径。以读取两个版本的路径为例：

| 运行地址 | 操作 | 含义 |
| --- | --- | --- |
| `0x538317C8` | 调用 `0x538349D8` | 读取候选包的两个四字节组件版本 |
| `0x538317E4` | 调用 `0x53755814` | 获取相机当前第一个组件版本 |
| `0x538317E8` / `0x538317EC` | `cmp r6, r0` / `blo 0x5383188C` | 候选版本按无符号数**低于**当前版本时拒绝 |
| `0x538317F4` / `0x53831800` | 获取当前第二个版本并执行 `blo` | 第二个组件同样只拒绝低版本 |

读取三个版本的分支在 `0x53831820` 开始，比较处是 `0x53831884`、`0x53831968`、`0x53831980`，也都是低于当前值才进入错误分支。由此可见，**这一函数并不要求候选版本严格大于当前版本；相等能通过这一函数**。但尚未穷举升级界面、引导程序和实际写入阶段的全部检查。理光[官方说明](https://www.ricoh-imaging.co.jp/english/support/digital/gr4_s.html)还明确提到，相机已是 1.03 时再次更新 1.03 可能显示“Update failed”。因此相同版本通过本函数，不等于通过完整更新流程。

候选包版本被重组成四字节无符号值。例如 `01 0B 0A 07` 被读成 `0x010B0A07`。其中一个读取函数 `0x53836888` 从包头对象的 `+0x38` 读取版本；另一个 `0x53836960` 从 `+0x50` 读取。另一路 `0x53836984` 从 `+0x4C` 读取反向存放的四字节版本。当前版本由相机上的组件版本对象提供。更改**候选包内**的升级器代码，无法改变相机在写入该包前运行的版本检查。

### 五段版本号不可直接追加

Version 页在 `0x531B8140` 起仅从同一个 32 位版本值提取四个 8 位分量，格式为 `%02d.%02d.%02d.%02d`。候选包比较器也只读取四字节。因此 `01.11.10.07.01` 不能直接表示为这一固件的版本号。在包头 `0x38` 处的四字节 `01 0B 0A 07` 后面，`0x3C` 原本是其它字段的 `03`；硬写第五个字节会覆盖它，而比较器读到的仍是 `01.11.10.07`。若要让版本略高于机身显示的 `01.11.10.07`，现有格式内应使用四段值，例如 `01.11.10.08`，而不是追加新段。新增第五段需要同时改造相机现有升级器和版本存储/显示逻辑，不能靠改候选包实现。

## 离线版本元数据试验

`tools/retag_update_version_experimental.py` 只改此样本已识别的 GR IV 版本副本：包头 `0x38`、`0x4C`（反向排列）、`0x50`，以及包尾 GR IV 机型记录的三个版本值。它保持解码载荷不变，重算 32 位加法校验，并拒绝机型记录或版本副本不一致的输入。**它没有补齐 XPAN 功能，也没有验证签名、内部校验、实机接受或失败恢复。**

离线验证结果：

- 目标仍为 `1.11.10.7` 时，输出与输入逐字节相同，SHA-256 为 `a2f664dfca034059eb0fd6e18ab08684c326b4a034d85c164dad7e1ec9b5655f`。
- 试设 `1.11.10.8` 时，仅版本位置和末尾加法校验发生变化，重新解包得到的载荷与原版逐字节相同。这个文件只是元数据实验，**不是 XPAN 固件，不应放入相机升级**。
- 对前述单字节测试载荷的重封装包再设置 `1.11.10.8`，也通过版本副本、长度、校验和解包内容核对；说明两项离线工具可以顺序使用，仍未验证实机接受。

若未来 XPAN 代码完成，版本策略应以相机实际显示的完整四段版本以及 CPU、SRIC、DSP 组件值为依据，选择刚好通过完整升级流程的最小值。随意设很高的版本可能使后续官方固件被判为过旧。理光[GR IV 固件说明](https://www.ricoh-imaging.co.jp/english/support/digital/gr4_s.html)和[GR WORLD 常见问题](https://www.ricoh-imaging.co.jp/english/support/qa/gr-world/)均说明更新后不能回退；因此升级包能重算加法校验，并不意味着可以安全测试或恢复。
